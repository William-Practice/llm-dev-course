## 二、环境与部署过程（含真实踩坑）

### 1. 安装 Ollama（用户级，无需 sudo）

本机 sudo 需要密码，官方脚本会装到 /usr/local，所以改用用户级安装：

```bash
# 注意：必须加 -L 跟随重定向！ollama.com 返回 307，漏了 -L 会得到 0 字节
curl -L -o /tmp/ollama.tar.zst https://ollama.com/download/ollama-linux-amd64.tar.zst
mkdir -p ~/.local/ollama
tar --zstd -xf /tmp/ollama.tar.zst -C ~/.local/ollama
```

实测：包 1,427,703,051 字节（1.36 GB），直连 **2.5 MB/s**，约 10 分钟装完。

> ⚠️ **踩坑 1**：`ollama.com/download/ollama-linux-amd64.tgz` 是 404，
> 现在的正确文件名是 `.tar.zst`（zstd 压缩）。

> ⚠️ **踩坑 2（浪费了半小时）**：测速时漏了 `curl -L`，服务端返回 307 重定向，
> curl 不跟随就得到 0 字节。我据此误判"网络不通/代理没开"，
> 实际加上 `-L` 后直连有 2.5MB/s。**排查下载问题先看 HTTP 状态码，别只看速度。**

### 2. 启动服务

```bash
export OLLAMA_MODELS=/data/ollama-models     # 模型存 /data，别撑爆家目录
~/.local/ollama/bin/ollama serve             # 默认监听 127.0.0.1:11434
```

验证：`curl http://localhost:11434/api/version` → `{"version":"0.34.4"}`

### 3. 拉取模型

```bash
ollama pull qwen2.5:1.5b        # 986 MB，实测几分钟
```

### 4. 注册微调模型 —— 遇到两个 Ollama 的新限制

**踩坑 3**：直接写 `ADAPTER <lora目录>` 会报错：
```
Error: LoRA adapters are no longer supported
```
Ollama 0.34.4 已经移除了 ADAPTER 指令（老教程里的写法全失效了）。

**踩坑 4**：改成合并后导入，用 `FROM <合并后的safetensors目录>` 又报：
```
Error: unsupported MLX architecture: model "Qwen2ForCausalLM"
```
Ollama 从 safetensors 导入时走的是 MLX（Apple 框架）路径，Linux 上不吃这套。

**解决路线**：LoRA 合并 → 转 GGUF → 从 GGUF 导入
```bash
# ① 合并 LoRA 到基座（CPU 执行，避免 4GB 显存不够）
python merge_lora.py
#    → /data/models/Qwen2.5-1.5B-kaoyan-merged（2.89 GB）

# ② 转 GGUF（llama.cpp 的转换脚本）
python convert_hf_to_gguf.py /data/models/Qwen2.5-1.5B-kaoyan-merged \
       --outfile kaoyan-qwen.gguf --outtype f16

# ③ 从 GGUF 注册
ollama create kaoyan-qwen -f Modelfile
```


## 四、技术要点

### OpenAI 兼容接口

Ollama 提供 `/v1/chat/completions`，与 OpenAI SDK 完全兼容：

```python
# 用 urllib（零依赖）
req = urllib.request.Request(
    "http://localhost:11434/v1/chat/completions",
    data=json.dumps({"model": "qwen2.5:1.5b", "messages": [...], "stream": False}).encode(),
    headers={"Content-Type": "application/json", "Authorization": "Bearer ollama"})
```

也可以直接用 OpenAI SDK：
```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
client.chat.completions.create(model="qwen2.5:1.5b", messages=[...])
```

`call_local_model()` 封装了这套调用，`call_openai_compatible()` 还能改 base_url
指向别的服务（vLLM / LM Studio 等）。

### 多轮对话的历史管理

```python
history = [{"role": "system", "content": "..."}]
history.append({"role": "user", "content": q})
reply, t = call_local_model("", model, messages=history)
history.append({"role": "assistant", "content": reply})   # 把回答也存回历史
```

调用失败时要把刚加入的 user 消息 pop 掉，否则历史里会留一条没有对应回答的消息。

### 服务端/客户端职责划分

- `server_check.py`：**可以独立运行**，做健康检查 + 模型清单 + 提供调用函数
- `client.py`：启动先调 `check_service()`，服务没起就提示 `ollama serve`，
  而不是直接抛连接异常 —— 用户体验差别很大
