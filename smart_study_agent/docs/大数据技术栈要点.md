# 大数据技术栈核心要点

## Kafka（消息队列）
- 分区（Partition）是并行处理的基本单位，一个分区只能被同一消费者组内的一个消费者消费
- 副本（Replica）保证高可用，leader 负责读写，follower 同步；ISR = 与 leader 保持同步的副本集合
- offset 是消息在分区内的唯一位置编号，消费者通过提交 offset 记录消费进度
- 生产者 acks 参数：0（不等确认，最快）1（leader 确认）all（所有 ISR 确认，最安全）
- 适用场景：日志采集、流式数据处理、系统解耦、削峰填谷

## Flink（流处理）
- 以事件流为核心，批处理是流处理的特例（流批一体）
- 水位线（Watermark）用于处理乱序数据，表示"该时间之前的数据都到齐了"
- 窗口（Window）：滚动窗口（Tumbling，不重叠）、滑动窗口（Sliding，可重叠）、会话窗口（Session，按间隔划分）
- 状态（State）与检查点（Checkpoint）：Checkpoint 基于 Chandy-Lamport 算法做分布式快照，实现精确一次（Exactly-Once）语义
- Checkpoint 存到 HDFS/S3，失败后从最近 Checkpoint 恢复
- 时间语义：事件时间（Event Time）、处理时间（Processing Time）、摄入时间（Ingestion Time）

## Spark（批处理）
- 核心抽象是 RDD（弹性分布式数据集），不可变、可分区、可并行操作
- 算子分两类：Transformation（懒执行，如 map/filter/join）、Action（触发计算，如 count/collect/save）
- DAG 调度：Transformation 构成有向无环图，遇到 Action 才提交执行
- 宽依赖 vs 窄依赖：窄依赖每个父分区只被一个子分区使用（可流水线）；宽依赖需要 shuffle
- Shuffle 是性能瓶颈，能避免就避免（如用 reduceByKey 代替 groupByKey）
- DataFrame/DataSet 比 RDD 有 Catalyst 优化器和 Tungsten 执行引擎，性能更好

## HDFS（存储）
- 主从架构：NameNode 存元数据（文件到块的映射），DataNode 存实际数据块
- 块大小默认 128MB，副本数默认 3
- 写流程：客户端请求 → NameNode 返回可用 DataNode 列表 → 流水线写入 → 逐级确认
- 读流程：客户端问 NameNode 块位置 → 就近读取 DataNode
- 单点故障：NameNode 是单点，用 HA（Active/Standby + ZooKeeper 选主）解决

## 湖仓一体（现代栈）
- Paimon / Iceberg / Hudi 是三大湖仓方案，提供 ACID、时间旅行、Schema 演进
- 相比 Hive 数仓：支持流式写入（CDC 入湖）、行级更新删除、小文件自动合并
- 典型架构：Flink CDC 采集业务库 → Paimon 湖仓分层（ODS/DWD/DWS/ADS）→ OLAP（Doris/StarRocks）查询
